## 4. 问题详情

### FB-001 P1 注册/登录：邮箱、密码格式不规范无提醒

**现象**：注册时填写不规范的邮箱地址或不符合规则的密码，页面没有校验提示，反馈原话「注册邮箱、密码格式不规范无提醒」。

**期望**：输入失焦或提交时给出明确的格式要求与错误原因；服务端同步校验并返回可读错误，而不是静默接受或给出无法理解的失败。

**备注**：需确认当前注册方式（需求文档 4.1 为「演示登录或 Supabase 登录」）下邮箱/密码的校验规则由谁负责，现象截图为空，待补充复现步骤。

### FB-002 P1 训练对话：语音输入有问题

**现象**：训练工作台底部「语音输入」按钮存在但功能异常（反馈原话「语音输入有问题」，无截图）。具体表现（点击无响应 / 无法录音 / 无法转写 / 转写错误）待反馈人补充。

**关联需求**：需求文档 4.5 要求「语音输入失败时保留文字输入路径」，需同时验证降级路径是否正常。

### FB-003 P1 训练地图：完成训练后地图不更新

**现象**：反馈原话「训练地图不会因为训练过而更新」。复盘页实际已有 4 条训练记录（见 FB-014 截图：AI 客服不准确×2、报表导出慢、数据大屏需求，本周训练 4/5），训练地图未体现相应状态变化。

**期望**：完成一轮训练后返回训练地图，对应任务的状态（待训练 / 已覆盖 / 待复练）即时刷新，与训练记录一致。

### FB-004 P2 训练模式：命名与需求文档不一致

**需求文档 4.1 原文**：「训练模式、严格模式和练习模式」（图1）。

**产品实际**（图2、图3）：切换项为「练习、独立、严格」三项。

**差异**：

- 文档中的「训练模式」在产品中无对应项；
- 产品中的「独立」在需求文档中无定义，无法判断对应文档哪个概念。

**建议**：统一命名，或在需求文档中补充「独立模式」的定义及三者差异说明。

### FB-005 P1 训练模式：切换模式导致计时器每次 +1 秒

**现象**：反馈原话「练习、独立、严格模式切换时，严格模式会增加时间」「它最初设定应该是 6min，但是每次切换 +1s」。图3 中严格模式剩余时间为 **06:16**，与 6 分钟初始设定不符。

**复现**：进入训练 → 记录初始剩余时间 → 在练习/独立/严格之间反复切换 → 每切换一次剩余时间约 +1 秒。

**期望**：模式切换按既定规则重置或保持计时，不产生累计漂移；严格模式时长固定为 6 分钟。

**影响**：训练时长数据失真，影响严格模式的评分口径与可信度。

### FB-006 P0 复盘与复练：不能查看上次提交

**现象**：复盘页只能看到训练记录的摘要信息（标题、主要行为、待复练标签、本次评分、复练模式/复练结果、导师点评），无法查看上一次训练的提交内容（访谈对话过程、判断内容、证据选择）。

**伴随现象**：该账号已完成世界 1 并揭示后果（图6 顶部显示「世界 1 / 3」「后果揭示」），但复盘页「世界决策记录」区域仍显示「还没有已完成的世界决策」（图7），说明决策数据未同步或未保存。

**期望**：复盘页可完整回看上次提交内容；世界决策记录与实际完成情况一致（需求文档 4.1：「训练历史、复盘和局部复练」）。

### FB-007 P1 世界工作台：世界 1/2/3 不可理解、看不到 3 个世界

**需求文档 4.4 原文**（图4）：「世界 1、世界 2、世界 3 依次验证同一底层判断习惯」；功能范围表标注入口为「今日训练 → 世界工作台」。

**现象**：反馈原话「我没理解世界工作台1、2、3，也没看到 3 个相同的界面」。图6 顶部仅显示「世界 1 / 3」，看不到世界 2、世界 3 的入口或进度，也不清楚三者是顺序解锁还是并列选择。

**建议**：在世界工作台内明确展示 1/2/3 的进度与切换入口，说明三个世界的关系（依次验证同一判断习惯）与推进条件。

### FB-008 P1 多角色训练：未找到入口

**需求文档**：4.5「多人角色训练支持运营、财务和一线员工等独立会话」；功能范围表标注「已实现本地版本」，主要入口为「训练地图」。

**现象**：反馈原话「多角色训练没找到」，在训练地图未见入口。

**需确认**：是入口未展示、层级过深，还是本地版本未在服务端环境开放。

### FB-009 P1 团队：加入后无任何查看其他成员的视图

**现象**：反馈原话「加入团队后，只能看到加入团队，没看到负责人、学习者有什么可以查看其他人的地方」。团队内既无成员列表，也无查看他人训练情况的入口。

**影响**：与 FB-011 直接相关——没有「主管查看下属」的视图，导致主管点评只能登录下属账号完成。

**期望**：负责人可查看团队成员及其训练概况；学习者可查看团队信息；点评入口挂在团队/成员视图上，而不是被点评者的个人页面。

### FB-010 P2 导师/主管点评：存在限制但无提示

**现象**（图5）：点评输入框填写内容「hh」后，「保存点评」按钮呈置灰/不可保存状态，界面没有任何原因提示，疑似存在字数下限等限制（同图中另一条已保存点评「hhhhh」长度更长）。

**期望**：在输入框旁标注限制规则（如最少字数），不满足时实时给出可读提示，而不是静默禁用按钮。

### FB-011 P0 导师/主管点评：点评流程与角色模型不符

**反馈原话**：「应该是主管可以点评下属，不是，下属白天使用平台，晚上主管登录下属的号进行点评。」

**解读**：点评功能目前挂在被点评者本人的训练记录页内（图7 中点评以练习生账号视角保存），主管无法以自己账号对下属记录发起点评，实际流程退化为「主管借用下属账号代写点评」，点评人身份失真。

**期望**：主管使用自己账号查看下属训练记录并留下点评；点评记录归属点评人（身份 + 时间），与学员本人备注区分。

**关联**：FB-009（团队查看视图缺失）、FB-010（点评限制无提示）。

### FB-012 P1 标准化考核：未看到

**需求文档**：功能范围表标注「标准化考核评分，已实现诊断版本」，主要入口为「资源中心」。

**现象**：反馈原话「标准化考核没看到」。

**需确认**：资源中心是否已放置入口、是否需要特定角色/权限才可见。

### FB-013 P0 世界工作台：无效输入可走完决策流程并获得正面后果

**现象**（图6，反馈原话「这个回答是认真的吗」）：

- 页面提示「当前未配置模型，本次回复由受治理的本地规则完成」「这次输入与当前世界关联不足，未计入正式证据」；
- 用户输入无意义内容「hhhh」，世界仅回复模板句「这个问题与当前的 B2C / AI 工具产品场景没有直接关系。请围绕当前需求、用户、使用现状、风险或替代方案继续提问。」；
- 随后仍显示「决策已提交」，并成功揭示后果「CEO 满意，会议快速结束」。

**问题**：本地规则兜底下，输入有效性校验与决策判定脱节——被判「关联不足、未计入正式证据」的输入不影响决策提交与后果走向，任意输入都能得到正面后果，训练结论失真。

**期望**：

- 无关联输入应阻断决策提交或要求重新调查，不应直接推进到后果揭示；
- 未配置模型时限制世界闭环流程，或明确标注当前为演示数据、不计入任何证据。

**参考**：`docs/incidents/2026-08-04-world-narrator-grounding.md`（世界叙述接地问题已有先例，`2026-08-05-world-workbench-related-question-formulaic-reply.png` 记录过同类模板化回复）。

### FB-014 P0 评分完整性：网页端可手动改分数

**现象**（图7）：复盘页「本次评分」数值（50）为前端 DOM 节点，反馈人通过浏览器开发者工具（Elements 面板选中 `<strong>50</strong>`）即可手动篡改页面上显示的分数。

**风险**：

- 若评分在前端计算或存储（本地状态 / localStorage），则分数可被任意修改并可能随记录提交，评分与能力证据的可信度不成立；
- 若仅为显示层可改（服务端数据不受影响），也需确认所有评分展示均来自服务端返回，而非前端可变状态。

**需验证**：篡改后刷新页面分数是否恢复；前端改分后提交/复练，服务端落库的分数是否被污染。

**期望**：评分由服务端计算与存储，前端只读展示；涉及评分的提交（复练结果、能力证据）一律经服务端校验。
