## 4. 本轮新问题详情

### RT-001 P1 语音输入：已联网仍提示「语音识别网络不可用」

**现象**（图1）：反馈人网络连接正常，点击语音输入后提示「语音识别网络不可用，可重试或直接输入文字。」

**代码定位**：`voice-input-button.tsx` 使用浏览器原生 SpeechRecognition（Web Speech API），浏览器 `network` 错误码映射为该文案（`:27`）。Chrome 的语音识别需将音频上传 Google 云端服务，目标用户网络环境下即使本机联网也无法访问，该错误必然复现；文案本身准确，但易被用户理解为「没联网」。

**定性**：FB-002 的「失败原因不可见」已修复；但语音功能在目标用户网络环境整体不可用。

**建议**：

- 接入可配置的服务端 ASR 或可用的国内识别服务；
- 短期至少在文案中说明服务依赖（如「在线识别服务连接失败」），避免误导；
- 文字输入降级路径已保留（满足需求 4.5），保持。

### RT-002 P2 训练模式：训练与练习语义重复，应更新需求文档

**背景**：FB-004 的修复方向是「产品向文档对齐」，现已完成。

**反馈原话**：「模式设定和需求文档一致了，但是训练和练习意思不是一个吗？应该更新的是产品需求。」

**问题**：根因在文档术语——「训练模式」与「练习模式」在中文语义上高度重叠，用户无法区分两者定位；对齐文档只是把歧义从产品搬回了文档。

**建议**：走需求变更而非代码修复：更新 PRD 4.1，或重新命名三种模式（如「练习 / 严格 / 复练」），或在文档中给出「训练 vs 练习」的明确区分定义（如训练=完整流程、练习=单环节），再同步产品文案与 `training-session.ts` 注释。

### RT-003 P1 复盘：查看上次提交内容长文本不换行

**现象**（图2）：「查看上次提交内容（对话与判断画布）」中，判断画布「核心问题」为长文本（用户粘贴的 PRD 段落），文字超出容器右边界不换行，内容被截断，页面出现横向滚动条（截图左下红框）。

**复现**：提交包含长英文段落/长 URL/无空格长串的判断 → 复盘页查看上次提交 → 正文区域横向溢出。

**说明**：该区块为 FB-006 修复新增，功能已可用，属新增 UI 缺陷。

**建议**：容器启用 `overflow-wrap: anywhere`（或 `word-break: break-word`），flex/grid 子项补 `min-width: 0`；正文阅读区不应出现横向滚动。

### RT-004 P2 团队：团队名称/邀请码有长度限制但无提示

**现象**（图3）：团队名称输入「1」，「创建团队」按钮置灰，无任何原因说明。

**代码定位**：`team-workspace-panel.tsx:332` 创建团队要求名称 trim 后 ≥ 2 字符；`:335` 加入团队要求邀请码 ≥ 4 字符；两处均无提示文案。

**对比**：同文件点评输入框已有现成的提示模式「点评内容至少 4 个字（当前 X 字）」（`:302-303`），属同类遗漏而非能力缺失。

**建议**：补齐「团队名称至少 2 个字（当前 X 字）」「邀请码至少 4 个字」的实时提示。

**关联**：与 FB-010 同类问题（限制无提示），FB-010 已修，此处漏网。

### RT-005 P1 团队：角色固定为创建者=负责人、其余=学习者，无指派入口

**现象**（图4）：成员卡仅显示「cyp 负责人·已加入」「张明（你）学习者·已加入」两种身份；创建者无法将其他成员设为导师或负责人。

**反馈原话**：「团队只有创建者、学习者区别，应该是创建者可以选择其他人的身份。」

**代码定位**：数据模型已有三种角色 `ROLE_LABELS = { owner: "负责人", coach: "导师", learner: "学习者" }`（`team-workspace-panel.tsx:20`），但加入流程固定产生 owner/learner 两种，`coach` 角色没有任何产生路径，也无角色变更交互。

**影响**：FB-011 要求的「主管/导师以自己身份点评下属」依赖角色体系；coach 角色无法产生，点评权限闭环仍然走不通。

**建议**：负责人可在成员卡上变更他人角色（owner/coach/learner 三级），点评等权限按角色校验。

**关联**：FB-009、FB-011 → 回归状态「部分修复」的缺口即在于此。

### RT-006 P1 标准化考核：功能存在但入口不可发现（FB-012 未修复，已定位原因）

**现象**：反馈原话「没看到标准化考核」。

**代码定位**（发现路径断裂）：

1. 标准化考核功能已实现：`assessment-lab-panel.tsx`（「阶段 5 标准化考核研发 / 固定题序诊断试点」）；
2. 它挂在资源中心的第 7 个标签（共 8 个：社区案例 / 行业知识库 / 内容管理 / 计划与订阅 / 验证实验室 / 社区盲评 Beta / **标准化考核** / 受验证试点，`resource-hub-panel.tsx:77`）；
3. 资源中心唯一入口是训练地图页「开放资料 / 社区与行业知识库」卡片内的「打开资源中心」按钮（`app-shell.tsx:347`）——卡片文案与「考核」毫无关联；
4. 侧边栏主导航（今日训练 / 训练地图 / 复盘与复练 / 我的能力）没有资源中心。

**结论**：用户按 PRD 提示去「资源中心」找考核，但资源中心入口伪装成知识库卡片、考核又藏在第 7 个标签，发现路径断裂，「没看到」是必然结果。

**建议**：在侧边栏或训练地图增加「标准化考核」直达入口；短期至少让资源中心入口卡片文案覆盖考核；同步评估资源中心 8 个标签的信息架构。
