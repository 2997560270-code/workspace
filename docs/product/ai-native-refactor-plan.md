# Product Drill AI 原生重构方案

日期：2026-07-23

## 1. 决策摘要

Product Drill 不再定位为“固定 PM 训练流程中的 AI 角色扮演和评分工具”，而定位为：

> 面向产品岗位候选人、转岗者和需要承担产品决策职责的人，通过受约束的因果情境、可追溯决策证据和跨情境验证，持续发现并改变产品发现判断习惯；在完成效度验证后，提供可用于求职或内部人才评估的量化结果。

核心不是聊天、课程、题库数量或总分，而是：

```text
判断习惯假设
+ 因果情境世界
+ 决策事件
+ 自适应挑战选择
+ 判断证据图谱
+ 跨情境迁移验证
```

第一版只验证一个判断习惯：**证据不足时过早进入解决方案**。

## 2. 当前产品诊断

当前实现是一条固定状态机：

```text
interview -> judgment -> feedback -> retry -> complete
```

AI 已经替代部分人工执行，但没有改变流程本身：

- `training-session.ts` 固定五个阶段，并以关键词判断角色、流程、影响、替代方案和指标是否被覆盖。
- `app-shell.tsx` 固定呈现今日训练、训练地图、情境访谈、判断画布、反馈、复练和能力画像。
- `ai/pipeline.ts` 已使用结构化输出和证据消息校验，这是可保留基础；但最终仍输出五维评分和 `totalScore`。
- `evaluation.ts` 的降级评分依赖关键词、文本长度和消息数量，无法证明判断行为。
- `ability-profile.ts` 根据训练次数、维度分数和同题复练生成“稳定”等状态，不能证明跨情境迁移。
- Supabase 表结构围绕 session、message、judgment、evaluation、retry 和 ability evidence，尚未表达世界状态、决策事件、判断假设及迁移关系。
- 分析事件仍围绕 `judgment_submitted`、`evaluation_viewed` 和 `retry_completed`，无法衡量假设识别与迁移。

结论：当前产品属于 **AI 增强的人工训练流程**，不是 AI 驱动的新流程。

## 3. 目标产品主链路

### 3.1 首次使用

```text
进入第一个高区分度因果世界
-> 自主调查、询问或请求信息
-> 提交决策事件
-> 世界产生后果或反证
-> AI 形成暂定判断习惯假设
-> 第二个世界提供针对性干预
-> 第三个陌生世界进行无提示迁移验证
-> 生成判断证据画像
```

### 3.2 日常使用

```text
判断证据图谱
-> 找到最重要且最不确定的假设
-> 生成“下一最佳挑战”
-> 新决策事件
-> 更新支持证据、反证和置信度
```

用户可以接受、推迟或在未来带入真实问题。训练地图和场景库降为次级探索入口。

### 3.3 决策事件

每次核心行为必须在结果揭示前提交：

- 当前判断；
- 选择的行动；
- 预期结果；
- 置信度；
- 放弃的备选方案；
- 当前依据的证据。

聊天消息、关键词和画布完成度都不能独立证明能力。

### 3.4 反馈与迁移

- 默认先承诺决策，再揭示后果和反馈。
- 决策前提示记录为辅助证据，不能证明独立判断。
- 同情境修正只证明理解反馈。
- 只有在陌生世界中的无提示改善，才能形成模拟迁移证据。

## 4. 产品模块重构

| 当前模块 | 决策 | 新模块/行为 |
| --- | --- | --- |
| 今日训练 | 替换 | 下一最佳挑战：展示为何现在验证它，但不泄露考点 |
| 首次能力诊断 | 替换 | 三世界校准冲刺，形成首个判断习惯假设 |
| 训练地图 | 降级 | 社区世界与自由探索入口，不负责主路径 |
| 情境访谈 | 重构 | 世界工作台：询问、查看证据、请求数据、采取行动 |
| 产品判断画布 | 重构 | 决策事件提交器，不再是必经页面阶段 |
| 证据反馈 | 重构 | 后果回放、证据链、反事实路径和不确定性 |
| 局部复练 | 删除旧逻辑 | 改为新世界迁移测试，不在原题上判定能力提升 |
| 能力雷达/状态 | 替换 | 判断证据画像：假设、触发条件、支持/反驳证据、迁移状态 |
| 训练历史 | 重构 | 决策与后果时间线，而不是总分列表 |
| 能力证据 | 保留概念、换模型 | 从技能计数改为判断证据图谱 |
| 总分 | 从训练移除 | 训练阶段只显示证据与不确定性 |
| 正式考核 | 新增但延期 | 独立题池、固定条件、行为等级和置信区间 |
| AI 增强考核 | 延期 | 与独立判断模块分开报告 |
| 赛季排名 | 延期 | 独立竞赛题池；不作为招聘全球排名 |
| 社区盲评 | 封闭 Beta | 匿名、随机派题、证据化理由、保留分歧 |
| 评审质量投票 | 公开 Beta | 只影响评审信誉和复审路由，不改候选人成绩 |
| 评审贡献额度 | 公开 Beta | 质量结算后兑换有限托管训练次数 |

## 5. 首版因果世界

三个世界只测试同一个底层习惯，但使用不同表面情境：

1. 高权威需求方要求立即增加一个功能。
2. 大客户以续约压力推动一项解决方案。
3. 增长数据下降后，团队要求复制竞品功能。

每个世界版本必须包含：

- 不可变事实和因果规则；
- 角色、利益和信息边界；
- 初始可见事实与揭示条件；
- 用户可执行的调查和决策动作；
- 状态变化和可观察后果；
- 对应判断习惯及反证条件；
- 行为锚点和禁止推断项；
- 来源说明、版本和治理状态。

AI 可以改变语言、行业细节和角色表达，但不能改变世界真相、因果关系或评分依据。

## 6. AI 能力边界

### 保留

- OpenAI Responses API 的服务端调用；
- Zod 结构化输出；
- 模型版本、世界版本和 Rubric 版本记录；
- 证据 ID 与原始内容一致性校验；
- 超时、解析失败、监控和限流；
- 确定性演示降级路径。

### 重构为五个职责

1. **World Narrator**：在世界规则内生成角色回应和事件表达。
2. **Behavior Observer**：从决策事件提取可观察行为，不下最终结论。
3. **Hypothesis Updater**：更新支持证据、反证、适用条件和置信度。
4. **Intervention Generator**：在决策承诺后生成后果回放和反事实挑战。
5. **Challenge Selector**：从有限候选世界中选择最能减少关键不确定性的下一项。

第一版不实现通用贝叶斯优化或自由生成世界。选择器只需在三个已治理世界间按明确规则选择。

### 降级规则

- 确定性模式可完成演示，但结果标记为非正式。
- AI 失败时不得静默使用关键词规则生成正式证据。
- 无法验证证据来源时输出“证据不足”，而不是猜测。

## 7. 领域与数据模型

第一版新增最少必要模型，不建设考核、排名和社区表：

| 模型 | 作用 |
| --- | --- |
| `causal_worlds` | 世界身份、状态和当前版本 |
| `causal_world_versions` | 不可变规则、角色、事实、动作、后果及治理信息 |
| `challenge_runs` | 一次世界运行及其证据条件 |
| `world_events` | 用户动作、世界响应和状态变化的追加式时间线 |
| `decision_events` | 判断、行动、预期、置信度、备选和依据 |
| `interventions` | 提示、反馈、反事实及其发生时机 |
| `judgment_hypotheses` | 可证伪的判断习惯假设及当前置信度 |
| `hypothesis_evidence` | 决策、后果、辅助状态和迁移关系 |

现有 `training_sessions.snapshot` 可暂时作为读取缓存，但不能继续作为新模型唯一事实源。旧训练记录保持只读，不做破坏性迁移。

### 第一版 API

```text
POST /api/challenge-runs
POST /api/challenge-runs/:id/actions
POST /api/challenge-runs/:id/decisions
POST /api/challenge-runs/:id/reveal
POST /api/challenge-runs/:id/interventions
GET  /api/judgment-profile
```

社区、排名、充值和正式考核 API 不进入第一版。

## 9. BYOK 与开源边界

- 应用代码采用 AGPL-3.0；正式发布前进行法律复核。
- 第一版自托管 BYOK 使用部署环境变量，不把密钥发送到 Product Drill 官方服务。
- 托管账户级 BYOK 和充值次数延后，避免先建设密钥托管与计费。
- 开源部署可生成非官方诊断结果。
- 官方考核题池、校准数据、固定模型评分和成绩签发保持受控。

## 10. KPI 与验证

### 第一版核心结果

**暂定独立迁移率**：在第一个世界出现目标习惯的用户中，有多少人在第三个陌生世界无提示减少该行为。

在获得独立评审者前，该指标只能用于产品试验，不能称为已验证能力提升。

### 质量指标

- 证据引用有效率：所有判断必须能回到真实决策事件。
- 重复分析一致性：同一输入不应产生相反习惯结论。
- 世界规则违背率：AI 不得创造与世界版本冲突的事实。
- 辅助污染率：受提示决策不得被标记为独立证据。
- 用户理解率：用户能否指出结论依据和仍不确定之处。

### 运营驱动指标

- 首个决策事件完成率；
- 三世界校准冲刺完成率；
- 下一最佳挑战接受率；
- 七日内再次挑战率。

### 守护指标

- 对话或真实项目内容进入分析事件的比例必须为零；
- 降级结果进入正式画像的比例必须为零；
- 单次完整校准的模型成本和失败率；
- 不同背景用户的任务退出率和异常差异。

没有基线数据前不设置虚假百分比目标。先运行封闭试验，再根据置信区间设发布门槛。

## 11. 分阶段路线图

### 阶段 0：建立可开发基线

- 保存并提交当前未提交改动，避免与重构混杂。
- 为旧固定流程建立可回放基线。
- 完成 AGPL 许可证法律确认后再添加正式许可证。
- 把本方案拆成 GitHub Epics 和 Issues。

退出条件：当前构建、单元测试和 E2E 可重复通过，旧数据可读取。

### 阶段 1：AI 原生核心 MVP

- 定义一个判断习惯和三个因果世界。
- 实现 world event、decision event、intervention 和 hypothesis evidence。
- 实现受约束世界运行与承诺后反馈。
- 实现第三世界独立迁移验证。
- 首页改为下一最佳挑战，能力页改为判断证据画像。
- 支持自托管 BYOK 和确定性演示。

退出条件：端到端完成三世界闭环；所有证据可追溯；辅助与独立证据严格分离。

### 阶段 2：邀请制验证

- 招募目标用户进行封闭试验。
- 开放合作入口，邀请 PM、招聘经理或研究者参与世界审核。
- 建立隐藏锚例和盲评操作流程。
- 采集系统重复性、用户理解和暂定迁移基线。

退出条件：找到可复现的用户价值信号；至少获得独立评审反馈；未发现核心世界规则失真。

### 阶段 3：社区盲评 Beta

- 随机派题、匿名化、利益冲突限制。
- 评审必须提交 Rubric、证据、理由和置信度。
- AI 聚合但保留原始评价和分歧。
- 先不提供贡献额度和公开排名。

退出条件：评审供给能够覆盖提交；有足够数据评估评审一致性和滥用模式。

### 阶段 4：公开社区与赛季挑战

- 增加评审质量投票、信誉和复审路由。
- 质量结算后发放有限托管训练额度。
- 发布独立赛季挑战榜和竞赛题池。
- 增加限流、关联账户检测和异常审核。

退出条件：排名不影响正式结果；奖励未造成明显垃圾评审；题目质量可以被持续监控。

### 阶段 5：标准化考核研发

- 完成岗位分析和能力主张矩阵。
- 分离训练、试验、考核和锚题池。
- 先使用固定或受控多阶段考核，不做全自适应考试。
- 建立独立判断模块和单独的 AI 增强工作样本。
- 研究评分一致性、等值、公平性和岗位表现关系。

退出条件：达到预先定义的效度门槛前，只发布诊断报告。

### 阶段 6：受验证考核试点

- 仅由合作机构或企业组织受验证场次。
- 验证身份、统一环境和过程记录，异常由人工复核。
- 输出产品发现判断等级和置信区间。
- 量尺分、百分位和招聘使用按证据逐步开放。

## 12. 首版明确不做

- 不覆盖完整 PM 能力；
- 不发布训练总分；
- 不发布招聘合格线或行业百分位；
- 不实现自由生成无限世界；
- 不实现 IRT、CAT 或复杂推荐算法；
- 不实现完整社区投票和奖励；
- 不实现赛季排名；
- 不实现托管充值计费；
- 不实现自动摄像头或生物识别监考；
- 不重写现有设计系统；
- 不同时维护多模型路由。

## 15. 已知限制

- 当前没有用户基线、专家治理组或招聘效度数据。
- 社区盲评只能产生暂定诊断，不能代替岗位效度验证。
- “不可复制”不能在零用户阶段被承诺；壁垒必须由世界校准、纵向证据、评审可靠性和外部结果逐步形成。
- 当前工作区存在大量未提交改动，任何代码重构前必须先建立干净、可回滚的方向 A 基线。
