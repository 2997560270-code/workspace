## 4. 本轮新问题

### RT-007 P1 语音：识别报错后麦克风未释放

**现象**（图1）：语音识别已提示「Chrome 语音识别需将音频上传到云端识别服务，当前网络无法访问该服务」，但浏览器标签页的麦克风图标（红框）仍处于占用状态——提示说用不了，设备却一直在录。

**代码定位**：`voice-input-button.tsx` 的 `onerror`（`:58-61`）只更新提示与状态，从不调用 `recognitionRef.current?.stop()` / `abort()`；`onend`（`:63`）仅复位状态也不 stop。network 错误场景下 Chrome 可能长时间持有麦克风（onend 不触发或延迟触发）。

**影响**：

- 麦克风常亮引发「被监听」的隐私疑虑，持续占用系统设备；
- 状态机隐患：错误态下再次点击会走 `start()` 分支，旧识别器若未真正结束可能叠加。

**建议**：`onerror` 内立即 `abort()`（对 network 错误，`abort()` 比 `stop()` 更能立即释放）；`onend` 兜底释放；补一条「报错后麦克风图标熄灭」的回归用例。改动只有几行，建议立即处理。

### RT-008 P1 团队：无法退出团队

**现象**：反馈原话「无法退出团队」。成员没有任何退出入口，负责人也无法移除成员。

**代码定位**：`/api/teams` 仅支持 `create / join / mentor_note / set_role` 四个 action（`route.ts:41-50`），无 leave/remove；成员类型含 `status: "active" | "invited" | "suspended"`，但没有任何界面能产生 suspended 或退出；本地团队存储同样无删人逻辑。

**影响**：进错团队、测试产生的脏成员无法清理。本地试用阶段「重建团队即可绕过」掩盖了缺口，服务端版上线后即成阻塞。

**建议**：补 `leave`（成员自愿退出）与 `remove`（负责人移除成员，含越权校验）；owner 退出需先转让或解散团队。

### 5.2 RT-003：修复未生效，需重新定位溢出元素

已核实的事实：

- 修复确实存在：`globals.css` 给 `.review-submission-block dd` 与 `.review-submission-block li p` 补了 `min-width: 0; overflow-wrap: anywhere; word-break: break-word`（705667b）；
- UI 使用的正是这个类名：`查看上次提交内容` 区块为 `review-submission-block`（`app-shell.tsx:1092,1110`）；
- 反馈人构建包含该修复（图1 语音新文案同属 705667b），复测仍溢出（图2）。

两个假设，按顺序排查：

1. **样式缓存**：反馈人 Ctrl+F5 强刷后复测一次；
2. **溢出源头在更上层容器**：`.review-layout` / `section.review-detail` 等 flex/grid 链上仍有 `min-width: auto` 的子项把整页撑宽——本次补丁只修了块内文本换行，没修外层容器收缩。用 DevTools 从 `documentElement` 的横向 `scrollWidth` 逐层向下找实际撑宽的元素。

**建议修复方按假设 2 主动复查，不要直接二次关闭。**

### 5.3 RT-005：角色指派已实现，需求演进为「邀请指定身份 + 自定义称谓」

已实现（705667b）：owner 在成员卡上可通过下拉将成员在 学习者/导师 间调整（`set_role`，owner 角色不可改，`team-workspace-panel.tsx:220-228, 256-264`）。

反馈人本轮原话：「团队只有负责人、学习者、导师区别，应该是创建者可以选择其他人的身份（由创建者提供称谓）。」对照现状，剩余缺口有两层：

1. **邀请时不能指定身份**：创建团队后的邀请固定产生学习者角色（`team-workspace-panel.tsx:163` 硬编码 `role: "learner"`），只能事后改；
2. **称谓固定为三种**：负责人/导师/学习者是写死的 `ROLE_LABELS`，反馈人要求「称谓由创建者提供」，即允许负责人自定义成员头衔（如「产品总监」），而非仅在三选一里挑。

**建议**：与 RT-008（退出团队）合并做一次「团队角色与生命周期」设计：邀请时可选身份、可自定义称谓、可退出/移除。称谓自定义需评估其在点评署名、权限校验中的展示口径（展示名 ≠ 权限角色，权限仍建议收敛在 owner/coach/learner 三级）。
