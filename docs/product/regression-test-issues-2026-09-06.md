## 4. 本轮新问题

### RT-007 P1 语音：识别报错后麦克风未释放

**现象**（图1）：语音识别已提示「Chrome 语音识别需将音频上传到云端识别服务，当前网络无法访问该服务」，但浏览器标签页的麦克风图标（红框）仍处于占用状态——提示说用不了，设备却一直在录。

**代码定位**：`voice-input-button.tsx` 的 `onerror`（`:82-87`）原先只更新提示与状态，从不调用 `recognitionRef.current?.stop()` / `abort()`；`onend`（`:90`）原先仅复位状态也不 stop。network 错误场景下 Chrome 可能长时间持有麦克风（onend 不触发或延迟触发）。

**修复状态**：✅ 本轮已修复（2026-09-06）。新增 `releaseRecognition()`（`:27-39`），在 `onerror`、`onend` 兜底与卸载清理（`:57`）三条路径统一释放设备：先 `abort()`，失败退回 `stop()`，同一识别器只释放一次；错误态下同时清空 `recognitionRef`，避免旧识别器叠加。

**影响**：

- 麦克风常亮引发「被监听」的隐私疑虑，持续占用系统设备；
- 状态机隐患：错误态下再次点击会走 `start()` 分支，旧识别器若未真正结束可能叠加。

**建议**：`onerror` 内立即 `abort()`（对 network 错误，`abort()` 比 `stop()` 更能立即释放）；`onend` 兜底释放；补一条「报错后麦克风图标熄灭」的回归用例。改动只有几行，建议立即处理。

### RT-008 P1 团队：无法退出团队

**现象**：反馈原话「无法退出团队」。成员没有任何退出入口，负责人也无法移除成员。

**代码定位**：`/api/teams` 回归时支持 `create / invite / join / mentor_note / set_role` 五个 action，但没有 `leave` / `remove`；成员类型含 `status: "active" | "invited" | "suspended"`，但没有任何界面能产生 suspended 或退出；本地团队存储同样无删人逻辑。

**修复状态**：✅ 本轮已修复（2026-09-06）。`/api/teams` 现支持九个 action：`create / invite / join / mentor_note / set_role` 加 `leave` / `remove` / `dissolve` / `set_title`（schema `route.ts:6-18`，分支 `route.ts:47-73`）。新增仓储 `leaveTeam` / `dissolveTeam` / `removeTeamMember`（`team-repository.ts:174,219,250`）与本地目录守卫 `canLeaveTeam` / `leaveTeamWorkspace` / `canRemoveTeamMember` / `removeTeamMember`（`team-workspace.ts:96-133`）；界面补「退出团队」「解散团队」与成员卡「移除」（`team-workspace-panel.tsx:408,421,423`）。规则：成员不能移除他人，也不能移除负责人；导师只能移除学习者；负责人还有成员时不能退出，需先解散团队；最后一名成员退出即自动解散。退出采用删除成员关系而非 suspended，账号可凭邀请码重新加入。

**影响**：进错团队、测试产生的脏成员无法清理。本地试用阶段「重建团队即可绕过」掩盖了缺口，服务端版上线后即成阻塞。

**建议**：补 `leave`（成员自愿退出）与 `remove`（负责人移除成员，含越权校验）；owner 退出需先转让或解散团队。

## 5. 复核详情（声称已修 vs 复测结果）

### 5.1 RT-002：训练/练习语义重复，已改名「诊断模式」

PRD 4.1 现文（本轮改名后）：

> - 诊断模式：完整做一遍诊断流程，不提供即时提示，结束后统一反馈，可进入能力画像；
> - 练习模式：针对单个环节练习，可请求轻提示、查看信息缺口、暂停总结，使用提示会被记录；
> - 严格模式：限时且角色有冲突目标，会提出成本、风险与价值质疑，用于高等级能力验证；

反馈人本轮原话与上轮完全相同（「训练和练习意思不是一个吗？应该更新的是产品需求」），据此采纳改名方案：**「训练模式」更名为「诊断模式」**，与「练习」彻底区分（诊断 = 完整跑一遍出结论；练习 = 单环节反复练）。

**修复状态**：✅ 本轮已修复（2026-09-06）。`TrainingModeSchema` 现接受 `诊断 / 严格 / 练习`，旧值 `训练 / 独立` 读取侧归一化为 `诊断`（`schemas.ts:5-7`）；模式选项 `TRAINING_MODE_OPTIONS = ["诊断", "严格", "练习"]`（`training-session.ts:8`）；迁移 `202609060002_training_mode_to_diagnosis.sql` 把 `training_sessions.mode` 约束扩为含 `诊断`。README、PRD 4.1、direction §5.4 同步更新。

### 5.2 RT-003：修复未生效，需重新定位溢出元素

已核实的事实：

两个假设，按顺序排查：

1. **样式缓存**：反馈人 Ctrl+F5 强刷后复测一次；
2. **溢出源头在更上层容器**：`.review-layout` / `section.review-detail` 等 flex/grid 链上仍有 `min-width: auto` 的子项把整页撑宽——本次补丁只修了块内文本换行，没修外层容器收缩。用 DevTools 从 `documentElement` 的横向 `scrollWidth` 逐层向下找实际撑宽的元素。

**建议修复方按假设 2 主动复查，不要直接二次关闭。**

### 5.3 RT-005：角色指派已实现，需求演进为「邀请指定身份 + 自定义称谓」

已实现（705667b）：owner 在成员卡上可通过下拉将成员在 学习者/导师 间调整（`set_role`，owner 角色不可改，`team-workspace-panel.tsx:270-279, 379-389`）。

反馈人本轮原话：「团队只有负责人、学习者、导师区别，应该是创建者可以选择其他人的身份（由创建者提供称谓）。」对照现状，剩余缺口有两层：

1. **邀请时不能指定身份（后端已支持，缺口只在 UI）**：后端 `invite` action 已接受 `role: z.enum(["coach", "learner"])`（`route.ts:8`），但 UI 建队后固定以 `role: "learner"` 发起邀请，用户无法在邀请时选身份，只能事后用下拉改；
2. **称谓固定为三种**：负责人/导师/学习者是写死的 `ROLE_LABELS`，反馈人要求「称谓由创建者提供」，即允许负责人自定义成员头衔（如「产品总监」），而非仅在三选一里挑。

**修复状态**：✅ 本轮已修复（2026-09-06）。

- **邀请身份**：建队表单（`team-workspace-panel.tsx:533`）与团队邀请区（`:360`）都可就地选择身份；本地团队把身份记在 `inviteRole` 上，加入时生效（`team-workspace.ts:75` `setTeamInviteRole`，`joinTeamWorkspace` 读 `team.inviteRole`）；远程走已有 `invite` action 传 `role`，切换身份会重新签发邀请码。
- **自定义称谓**：新增 `set_title` action（`route.ts:17,70`）、仓储 `setTeamMemberTitle`（`team-repository.ts:285`）与本地 `canSetTeamMemberTitle` / `setTeamMemberTitle`（`team-workspace.ts:135,147`），成员卡新增称谓输入框（`team-workspace-panel.tsx:395`）；迁移 `202609060001_team_member_title.sql` 给 `team_members` 加 `title` 列（最多 20 字，可空）。
- **展示口径**：按本页建议执行「展示名 ≠ 权限角色」——成员列表与成员概况显示「称谓 · 角色」，权限判断仍只看 `role`（owner/coach/learner）；称谓只有负责人能改，且负责人本人不可改；清空称谓即回退到角色名。

**剩余建议**：点评署名仍使用「账号名 + 角色」，暂不带自定义称谓；若要带，需要在点评文案与历史记录口径上单独评估。
