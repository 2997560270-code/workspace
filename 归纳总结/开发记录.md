# 开发记录

## 2026-06-22

- 约定：后续开发过程中遇到的问题、解决方式、值得保留的做法，都实时记录到本地归纳总结文件中。
- 本文件只同步到本地桌面 workspace，不同步到飞书云文档。
- 第 3 模块取舍：登录基础先使用 HttpOnly 本地开发 cookie，不急着接 Auth.js 第三方登录；数据库基础先落 Prisma schema，PostgreSQL 真实连接等进入需要持久化训练记录时再接，避免本地环境被数据库服务阻塞。
- 第 3 模块问题：登录后首页仍可能显示未登录页。处理方式：将首页标记为 `force-dynamic`，确保服务端每次读取最新 cookie；e2e 登录后等待页面网络稳定再断言工作台。
- 第 3 模块问题：临时启动 Next dev 检查接口后遗留进程会阻塞 Playwright webServer。处理方式：按 Next 提示的 PID 停止遗留进程，再运行 e2e；后续临时服务检查后要确认清理。
- 第 3 模块问题：原生表单 POST 到本地演示登录接口时，浏览器测试未完成登录跳转。处理方式：演示登录改成 GET 跳转并设置 HttpOnly cookie；正式账号体系接入时再替换为 Auth.js。
- 第 3 模块最终简化：本地演示登录改为客户端写入 demo cookie 后刷新首页，保证人工测试和 e2e 稳定；这不是正式安全方案，真实用户前必须替换为 Auth.js 或服务端登录。
- 第 4 模块取舍：AI 对话训练先使用确定性本地回复，保证训练创建、用户发送、AI 追问和 e2e 流程可跑通；真实模型 API 等后续接入密钥和计费边界明确后替换。
- 第 4 模块问题：桌面 `归纳总结/开发记录.md` 被其他程序占用，实时复制失败。处理方式：先更新工作区记录副本，模块收尾时重试同步到桌面。
- 第 4 模块问题：e2e 登录后立刻点击“开始训练”时，页面可能尚未完全水合，点击没有触发状态更新。处理方式：测试先等待“训练工作台”标题可见，再点击开始训练。
- 第 5 模块取舍：方案评分先使用固定 7 维度的规则评估，保证“提交方案 -> 展示总分/维度/具体问题”链路可测；真实严厉评分和上下文理解等接模型 API 后替换。
- 第 5 模块问题：工作台组件曾作为模块级 React element 放在 `panels` 常量中复用，e2e 点击开始训练偶发不触发。处理方式：按当前 view 渲染时创建 `<Workbench />`，避免状态组件被顶层常量复用。
- 第 5 模块问题：完整 e2e 并发运行时，状态型页面偶发点击后未等到更新；单独运行通过。处理方式：MVP 阶段 Playwright 设为单 worker，换稳定性，不追求测试并发速度。
- 第 6 模块取舍：自有产品分析先使用本地规则生成产品理解摘要、5 个追问和 3 条优化建议，先验证表单和结果展示链路；真实产品深挖等接模型 API 后替换。
- 第 7 模块取舍：对话历史先使用前端内存记录，完成训练并提交方案后即可复盘对话和评分；数据库持久化等到账号体系和真实训练数据稳定后再接。
- 第 7 模块问题：用户在输入框填写回答后如果直接点“提交方案”，历史详情看不到该输入。处理方式：提交方案时先把未发送草稿并入当前对话，再生成评分和历史记录。
- 第 7 模块问题：输入框提示“Enter 发送”，但按 Enter 只是换行，用户气泡不会出现在 AI 对话区，后续历史也容易误以为没有记录。处理方式：为 textarea 增加 Enter 提交，Shift+Enter 保留换行；同时修复发送按钮误传点击事件的问题。
- 第 7 模块问题：未点击“开始训练”时，输入框仍可输入但发送按钮禁用，导致用户以为输入已发送但 AI 对话和历史都没有记录。处理方式：输入内容后允许直接发送，发送时自动创建训练会话；同时给用户气泡增加“你”标签和浅蓝底，降低误看风险。
- 第 7 模块问题：对话区直接使用 grid 承载多条气泡，新增气泡后布局被撑开，用户气泡只露出“你”，内容不稳定显示；右上角“查看对话记录”按钮也没有跳转历史页。处理方式：新增独立消息流容器，用户气泡恢复白底黑字并固定“你 + 内容”两行展示，同时接通“查看对话记录”到历史页。
- 第 7 模块问题：用户希望气泡像常见聊天产品一样按内容长短自适应。处理方式：用户气泡改为只显示输入内容，白底黑字右对齐；短内容使用小气泡，长内容受最大宽度限制后自动换行，并禁止 flex 容器压扁气泡高度。
- 第 8 模块取舍：能力画像先基于当前会话内的历史评分做前端聚合，展示平均分、完成训练次数、最高分、综合进步、最近训练表现趋势、能力维度、高频短板和下一步推荐训练；长期画像等接数据库持久化后再做。
- 第 8 模块问题：趋势图里的“第 2 次”和统计卡片里的“2 次”、简介文案里的“高频短板”和标题文本会让 e2e 文本选择器冲突。处理方式：测试断言收窄到 `.metrics` 容器或 heading 角色，验证真实 UI 区块而不是宽泛文本。
