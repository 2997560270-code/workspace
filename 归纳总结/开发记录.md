# 开发记录

## 记录规则

- 只记录开发中踩过的坑、解决方式、值得后续复用的做法。
- 不记录重复问题、过程流水账和已经稳定下来的普通实现选择。
- 本文件只保留在本地桌面 `workspace/归纳总结`，不同步 GitHub 和飞书云文档。

## 2026-06-22

### 模块 3：登录与数据基础

- 坑：登录后首页仍可能显示未登录页。
  解决：让首页动态读取最新 cookie，并在 e2e 中等待工作台标题出现后再断言。

- 坑：本地临时启动的 Next dev 进程会占用 3000 端口，导致 Playwright webServer 启动失败。
  解决：遇到端口占用时按 Next 提示的 PID 停止旧进程，再跑 e2e。

- 坑：演示登录用表单 POST 时，浏览器测试里跳转和 cookie 状态不稳定。
  解决：MVP 演示登录改为客户端写 demo cookie 后刷新页面；正式用户体系再换 Auth.js 或服务端登录。

### 模块 4：AI 对话训练

- 坑：登录后立刻点击“开始训练”，页面可能还没完成水合，点击不会触发状态更新。
  解决：e2e 先等待“训练工作台”可见，再执行训练操作。

- 坑：桌面 `归纳总结/开发记录.md` 偶尔被其他程序占用，实时复制失败。
  解决：先更新工作区副本，模块收尾时再同步到桌面。

### 模块 5：方案提交与评估

- 坑：工作台组件曾作为模块级 React element 放进常量复用，状态更新偶发失效。
  解决：按当前 view 渲染时再创建 `<Workbench />`，避免状态组件被顶层常量复用。

- 坑：完整 e2e 并发运行时，状态型页面偶发点击后没有等到更新。
  解决：Playwright 暂设单 worker，优先保证 MVP 测试稳定。

### 模块 6：自有产品分析

- 坑：真实 AI/API 还没接入时，如果直接做复杂分析链路，测试会被模型、密钥和网络阻塞。
  解决：先用本地规则生成产品摘要、追问和优化建议，保证表单到结果的链路可测。

### 模块 7：对话历史

- 坑：用户输入后直接点“提交方案”，未发送草稿不会进入历史详情。
  解决：提交方案前先把当前输入并入对话，再生成评分和历史记录。

- 坑：输入框提示 Enter 发送，但 textarea 默认 Enter 是换行，导致用户以为消息已发送。
  解决：Enter 发送，Shift+Enter 换行，并修复发送按钮误传点击事件的问题。

- 坑：未点击“开始训练”时可以输入但发送按钮禁用，用户容易误以为内容已经进入对话。
  解决：允许输入后直接发送，并在发送时自动创建训练会话。

- 坑：用户气泡在布局里被压缩，只显示“你”，内容没有稳定展示。
  解决：新增独立消息流容器，用户气泡白底黑字右对齐，只显示用户输入内容，并按内容长短自适应宽高。

- 坑：“查看对话记录”按钮没有跳转历史页。
  解决：把按钮接到历史视图。

### 模块 8：能力画像

- 坑：趋势图的“第 2 次”和统计卡片的“2 次”会让 e2e 文本选择器冲突。
  解决：测试断言限定在 `.metrics` 容器内。

- 坑：简介文案里的“高频短板”和模块标题同名，宽泛文本选择器会匹配多个元素。
  解决：标题类断言改用 heading 角色。

### 总验收后修复

- 坑：`提交方案` 复用了普通发送逻辑，导致生成评估前又追加一轮 AI 追问。
  解决：拆出只追加用户最终答案的逻辑，提交方案时不再触发 AI 追问。

- 坑：切换行业场景只改了下拉框状态，没有同步到当前训练会话，历史记录仍显示旧场景。
  解决：切换下拉框时同步更新当前 session 的 `scenario`，并显示切换成功提示。

- 坑：未开始训练前对话框有默认 AI 文案，且“发送”会自动创建训练，和“必须先完成场景设置再开始”的流程冲突。
  解决：未开始训练时消息流保持空白，发送和提交按钮不触发对话；点击“开始训练”后才输出 AI 开场。

- 坑：AI 开场直接要求用户澄清问题，缺少对用户具体业务的确认。
  解决：开场先询问“您的具体业务是什么”，用户回答后再围绕所选行业场景和具体业务继续追问。

- 坑：切换行业场景只在侧栏显示提示，不在对话流里留下上下文。
  解决：已开始训练后切换行业场景，会追加一条 AI 气泡提示当前场景、模式和难度。
- 坑：切换行业场景保留了历史消息，但追问轮次仍按整段对话里的用户消息总数计算，导致新场景继续第 3/第 4 轮追问。
  解决：在 session 中记录当前场景开始时已有的用户消息数，切换场景后重新询问具体业务，下一次用户输入按新场景第 1 轮处理。

## 2026-07-01｜Windows 双击测试入口批处理解析问题

- 问题：模块测试入口 `.cmd` 初版使用 UTF-8 BOM、中文提示和错误的反斜杠转义引号，Windows 批处理双击/运行时可能无法正确进入项目目录。
- 解决：入口脚本改为纯 ASCII 内容，并使用标准批处理写法 `set "APP=..."`、`cd /d "%APP%"`；同时保留中文文件名入口并新增英文备用入口 `run-module01-tests.cmd`。
- 经验：`.cmd` 文件优先使用 ASCII 内容；中文说明放文档里，脚本内避免 BOM 和复杂中文输出。

## 2026-07-01｜Next 无法解析带 BOM 的 package.json

- 问题：PowerShell `Set-Content -Encoding UTF8` 写出的 `package.json` 带 BOM，`npm test` 可以运行，但 Next dev server 报 `package.json is not parseable`。
- 解决：使用 `.NET UTF8Encoding(false)` 重新写入 `package.json`，去掉 BOM。
- 经验：JSON、CMD、环境配置文件优先使用无 BOM UTF-8 或 ASCII，避免不同工具解析不一致。

## 2026-07-06 模块05记录：本地持久化与真实记录联动

- 本地存储适配层单独封装，测试时可用内存版 StorageLike 验证，不依赖浏览器环境。
- E2E 验证历史持久化时，不能只断言静态文案存在；应断言记录数量从默认 6 条变为 7 条，才能证明新记录真的被保存。
- PowerShell 字符串替换时，单引号中的 `r`n 会被当作字面文本写入文件；修复方式是使用 `[Environment]::NewLine` 或双引号换行，避免 TypeScript 编译失败。

## 2026-07-06 修复记录：多轮训练历史只保留最新一次

- 根因：历史记录 ID 由 `session.id` 派生；页面刷新或重新启动后 session 计数可能从头开始，导致新记录和旧记录同 ID，被历史保存逻辑当成同一条记录覆盖。
- 修复：`createTrainingHistoryRecord` 改为每次提交方案生成独立历史记录 ID，优先使用 `crypto.randomUUID()`，无可用随机 UUID 时使用时间戳 + 递增序号兜底。
- 测试：新增单元测试验证同一次 session 的两次历史记录 ID 不相同；新增 E2E 验证刷新后再次训练，历史记录累计到 2 条真实记录，能力画像同步显示真实记录 2。

## 2026-07-06 调整记录：能力趋势图变化不明显

- 问题：能力页“最近训练表现趋势”原先按固定分数比例换算 Y 坐标，接近分数例如 70 和 80 的视觉差只有约 16px，用户感知不明显。
- 修复：趋势线改为基于当前训练记录的最低分/最高分做局部归一化，把真实变化映射到更大的纵向区间，保留数据不变，只增强趋势可读性。
- 测试：新增 E2E 验证接近分数的趋势线纵向差异至少达到 90px，避免后续回退成不明显的固定比例展示。

## 2026-07-06 调整记录：能力趋势图增加坐标轴参数

- 需求：最近训练表现趋势需要坐标轴参数，突出训练结果变化性。
