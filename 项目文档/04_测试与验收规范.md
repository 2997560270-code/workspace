# 测试与验收规范

## 文档信息

- 状态：已确认
- 创建时间：2026-07-01
- 适用范围：Product Drill 所有模块

## 1. 测试原则

1. 每个模块开发前先定义测试方式。
2. 每个模块开发后必须告诉用户怎么手动测试。
3. 自动测试只能证明基础流程，最终以用户人工验收为准。
4. 测试入口文件名要体现当前测试模块。
5. 修复问题后需要重新说明测试步骤。

## 2. 测试类型

### 2.1 手动测试

用于确认视觉、交互、业务流程是否符合预期。

必须包含：

- 打开文件
- 操作步骤
- 期望结果
- 失败表现

### 2.2 自动测试

用于快速验证核心逻辑是否破坏。

可使用：

- Playwright 页面交互测试
- DOM 结构检查
- 文件存在检查
- 文档内容检查

### 2.3 兼容性测试

重点检查：

- 1366 × 768 笔记本尺寸
- 1920 × 1080 显示器尺寸
- 是否出现按钮遮挡
- 是否出现整页滚动和内部滚动冲突

## 3. 验收记录格式

```markdown
# YYYY-MM-DD_模块名称_验收记录

## 测试入口

填写入口文件。

## 测试环境

- 操作系统：Windows
- 浏览器：填写浏览器
- 视口：填写尺寸

## 测试步骤

1. 步骤一
2. 步骤二
3. 步骤三

## 期望结果

- 结果一
- 结果二

## 实际结果

- 结果一
- 结果二

## 验收结论

- 通过 / 不通过

## 后续问题

记录需要继续修复的问题。
```

## 5. 当前 demov3 重点测试路径

1. 训练设置确认流程。
2. 训练中更改设置并归档历史。
3. 训练完成后更改设置并归档历史。
4. 历史记录内部滚动。
5. 我的产品新增、切换、删除。
6. 能力画像展示。
