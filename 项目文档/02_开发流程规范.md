# 开发流程规范

## 文档信息

- 状态：已确认
- 创建时间：2026-07-01
- 适用范围：Product Drill 后续功能开发
- 关联入口：`../demov3.html`
- 关联文件：`../README-demov3.md`

## 1. 总原则

后续开发采用“测试先行、小步开发、单模块验收”的节奏。

固定循环：

```text
需求确认 → 开发计划 → 写测试 → 开发模块 → 自动验证 → 人工测试 → 同步记录 → 进入下一个模块
```

## 2. 每个模块的开发步骤

### 第一步：需求确认

输出内容：

- 需求说明
- 本次包含范围
- 本次不包含范围
- 人工审核点

存放位置：`01_需求与决策/`

### 第二步：开发计划

输出内容：

- 影响文件
- 测试策略
- 开发步骤
- 验收标准
- 回退方案

存放位置：`03_开发计划/`

### 第三步：先写测试

测试类型按模块风险选择：

- 静态 HTML demo：使用 Playwright 或 DOM 检查。
- React/Next 模块：优先写 Playwright e2e 或单元测试。
- 文档类改动：检查文件存在、内容完整、无不应出现的占位词。

### 第四步：开发模块

开发要求：

- 只改当前模块相关文件。
- 不顺手重构无关模块。
- 不改用户已确认的交互模块，除非用户明确要求。
- 保留可回退状态。

### 第五步：自动验证

验证内容：

- 页面能打开。
- 控件能点击。
- 状态能更新。
- 关键流程能跑通。
- 笔记本尺寸不遮挡。
- 控制台无阻断性错误。

### 第六步：告诉用户怎么测

每次开发完成后必须告诉用户：

1. 打开哪个文件。
2. 点击哪个导航。
3. 输入什么内容。
4. 期望看到什么结果。
5. 如果失败会表现为什么。

### 第七步：用户人工验收

用户确认后，再继续下一个模块。

如果用户反馈问题，当前模块优先修复，不进入新模块。

## 3. 测试入口命名规则

每次当前测试重点变化，测试入口文件名要同步变化。

格式：

```text
打开测试-demov3模块名称.cmd
打开测试-demov3模块名称.html
```

示例：

```text
打开测试-demov3训练设置确认流程.cmd
打开测试-demov3训练设置确认流程.html
```

## 4. GitHub 同步规则

默认不自动 push，除非用户明确要求。

用户要求 push 时，需要同步：

- 本次改动文件
- 打开入口文件
- 启动脚本
- README 或说明文档

不应同步：

- `.codegraph/`
- `归纳总结/`
- 临时截图
- 临时调试包
- 本地日志

## 5. 飞书同步规则

默认不自动同步飞书，除非用户明确要求。

用户要求同步时，需要同步：

- 当前 demo 文件
- 当前测试入口
- 启动脚本
- README 或说明文档
- 相关计划或验收文档

同步后需要回读文件列表确认文件存在。

## 6. 回退规则

每次重要节点建议使用 Git 提交或 tag 形成回退点。

回退说明应记录到：`06_版本记录/`

记录内容：

- 提交号或标签名
- 对应功能状态
- 可回退原因
- 回退风险

## 7. 开发完成汇报格式

每次完成开发后，回复用户时包含：

```text
已完成：说明改了什么
已验证：说明怎么验证
测试方式：说明用户怎么测
同步状态：说明是否同步桌面/GitHub/飞书
剩余风险：说明还没覆盖什么
```
