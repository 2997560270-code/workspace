## 7. 新项目开发复用策略

### 7.1 第一阶段：迁移纯逻辑

优先迁移以下文件到新工程：

```text
training-session.ts
training-config.ts
evaluation.ts
training-history.ts
product-analysis.ts
ability-profile.ts
auth.ts
```

迁移后先跑单元测试，确保旧逻辑不丢失。

### 7.2 第二阶段：按 Demo V3 重建 UI

严格按照 `demov3.html` 的页面结构和按钮位置拆分组件：

```text
HomePage
TrainingPage
ProductsPage
AddProductPage
HistoryPage
AbilityPage
AppLayout
SideNav
TopBar
```

要求：

- 不移动 Demo V3 已确认按钮位置。
- 不改变侧边栏动态交互逻辑。
- 不改变训练设置确认流程。
- 不改变产品档案左侧、AI 解读中间、成熟度右侧的结构。
- 不改变历史记录顶部参数和内部滚动逻辑。

### 7.3 第三阶段：接入正式数据层

在本地模拟数据通过后，再接入：

- 本地状态持久化。
- API route。
- 数据库模型。
- 文件上传处理。
- AI 接口。

## 8. 模块复用结论

| 模块 | 是否复用旧代码 | 复用方式 |
|---|---|---|
| 首页 | 部分复用 | 以 Demo V3 静态模板为准，旧 demov2 只参考文案思路 |
| 训练工作台 | 复用核心逻辑 | UI 重写，复用训练会话、评估、历史归档逻辑 |
| 我的产品 | 复用部分逻辑 | 复用产品分析函数，UI 和产品管理状态按 Demo V3 重写 |
| 添加产品 | 部分复用 | 表单和上传流程重写，分析逻辑复用 |
| 历史记录 | 复用部分逻辑 | 记录结构增强，UI 按 Demo V3 重写 |
| 能力画像 | 复用计算逻辑 | UI 按 Demo V3 重写 |
| 登录 | MVP 阶段复用 | 上线前替换真实认证 |
| 数据库 | 部分复用 | 旧 Prisma 作为基础，新增产品和评估模型 |
| 测试 | 大量复用 | 单测和 E2E 迁移到新目录 |
| 静态测试入口 | 部分保留 | 新项目需要重新建立稳定启动入口 |

## 9. 下一步建议

正式开发第一步建议不是直接写页面，而是先做“项目初始化与旧逻辑迁移”模块：

1. 在 `product-drill-mvp` 中初始化正式前端工程。
2. 迁移旧的纯逻辑模块。
3. 迁移并调整单元测试。
4. 跑通测试。
5. 再开始按 Demo V3 拆首页和布局。

这样可以保证：

- 视觉严格跟 Demo V3 对齐。
- 功能逻辑不从零浪费重写。
- 旧问题不会被带入最终 UI。
- 每个模块都有测试兜底。
