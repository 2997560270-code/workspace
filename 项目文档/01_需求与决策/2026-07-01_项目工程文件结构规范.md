# 项目工程文件结构规范

创建时间：2026-07-01  
关联工程目录：`C:\Users\A\Desktop\workspace\product-drill-mvp`

## 1. 目标

为 Product Drill MVP 正式开发建立统一的工程文件结构，让后续代码、测试、AI 提示词、设计资料、发布脚本和配置文件都有固定位置。

## 2. 根目录结构

```text
product-drill-mvp/
├─ apps/web/                       # Web 前端主应用
├─ packages/shared/                # 公共类型、常量、工具函数
├─ packages/prompts/               # AI 提示词模板
├─ packages/test-utils/            # 测试工具
├─ docs/                           # 工程内部文档
├─ scripts/                        # 开发、测试、发布脚本
├─ config/                         # 工程配置
└─ storage/                        # 本地上传与导出临时目录
```

## 3. 模块文件放置规则

| 模块 | 页面目录 | 业务组件目录 | 业务逻辑目录 | 测试目录 |
|---|---|---|---|---|
| 首页 | `apps/web/src/pages/` | `apps/web/src/components/domain/home/` | `apps/web/src/features/home/` | `apps/web/tests/` |
| 训练工作台 | `apps/web/src/pages/` | `apps/web/src/components/domain/training/` | `apps/web/src/features/training/` | `apps/web/tests/` |

| 历史记录 | `apps/web/src/pages/` | `apps/web/src/components/domain/history/` | `apps/web/src/features/history/` | `apps/web/tests/` |
| 能力画像 | `apps/web/src/pages/` | `apps/web/src/components/domain/ability-profile/` | `apps/web/src/features/ability-profile/` | `apps/web/tests/` |

## 4. AI 提示词放置规则

AI 提示词统一放在：

```text
packages/prompts/src/
├─ training/                       # 行业客户模拟、用户需求提出、客户咨询
├─ product-analysis/               # 自有产品解读、追问、成熟度评估
└─ evaluation/                     # 方案评估、能力画像、优化建议
```

页面组件不能直接硬编码大段提示词，避免后续难维护。

## 5. 测试放置规则

```text
apps/web/tests/
├─ unit/                           # 组件、函数、状态逻辑测试
├─ e2e/                            # 用户完整流程测试
└─ fixtures/                       # 测试样例数据
```

每个模块至少保留：

- 一个核心流程 e2e 测试。
- 一个关键状态或数据处理单元测试。
- 一份人工验收说明，放在 `项目文档/04_测试与验收/`。

## 6. 文档放置规则

- 项目管理文档：放在 `C:\Users\A\Desktop\workspace\项目文档/`。
- 工程内部文档：放在 `product-drill-mvp/docs/`。
- 开发踩坑总结：继续放在 `C:\Users\A\Desktop\workspace\归纳总结/`，不进入 GitHub 和飞书。

## 7. GitHub 与飞书同步规则

默认后续正式工程代码需要同步到 GitHub；飞书只同步适合协作查看的文档和 demo 产物。

不同步内容：

- `.codegraph/`
- `归纳总结/`
- 真实上传资料
- 本地临时日志
- 飞书认证缓存
- 大体积临时截图和录屏

## 8. 当前结论

`product-drill-mvp` 将作为后续正式 MVP 开发的规范工程目录。现有 `demov3.html` 暂时保留为设计和交互参考，不直接移动，等正式模块开发时再按测试先行流程逐步迁入。
